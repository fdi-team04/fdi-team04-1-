# 키워드 vs 임베딩 분류 비교 (11/23, 교수님 11/18 질문)

- 정답: 아영·예원 50건 판정 중 두 사람 답이 같은 기사 (실적 35건: 맞음 27·아님 8 / 목표가 50건: 합의 후 전부 맞음)
- 임베딩 모델: ko-sroberta-multitask(한국어 문장 임베딩), KR-FinBert-SC(금융 감성 모델 내부 표현)
- 코드: yw_run/embed_vs_keyword.py / 결과: out_yw/embed_vs_keyword.csv (기사 제목은 저장 안 함)

## 실적 호재 (뜻이 애매한 테마)
| 방법 | 남긴 기사 | 정밀도 | 진짜 호재를 놓친 수 |
|---|---|---|---|
| 키워드 v0 (실제 사용) | 35 | 77% | 0 |
| 임베딩 + 분류기 (ko-sroberta, 한 건씩 빼고 학습) | 30 | 83% | 2 |
| **임베딩 + 설명문 비교 (ko-sroberta, 학습 없음)** | 25 | **96%** | 3 |
| 임베딩 + 분류기 (KR-FinBert) | 27 | 85% | 4 |
| 임베딩 + 설명문 비교 (KR-FinBert) | 32 | 84% | 0 |
| (참고) 키워드 v1 (같은 50건 보고 고침) | - | 87~97% | 0 |

## 목표가 상향 (형식이 정해진 테마)
- 키워드: 정밀도 100%, 놓친 것 없음
- 임베딩 설명문 방식(ko-sroberta): 50건 중 47건만 남김 → 진짜 기사 3건을 놓침

## 결론 (분류 방식 선택 근거)
- **목표가 상향은 키워드가 더 낫다**: 제목 형식이 정해져 있어("OO, 목표가↑-XX증권") 키워드가 100% 맞히고, 임베딩은 오히려 3건을 놓침 → 최종 변수는 키워드로 만든다
- **실적처럼 뜻이 애매한 테마는 임베딩이 전망 기사를 더 잘 걸러냄** (77% → 83~96%). 교수님 말씀대로 '화재'(회사 이름 vs 사고), '실적 개선'(결과 vs 전망) 같은 구분에 강함
- 실적은 보류 테마라 지금 적용하지 않지만, 다시 볼 때는 임베딩 분류를 쓸 근거가 됨

## 한계
- 표본이 작음(실적 35건, 그중 '아님' 8건) → 정밀도 숫자는 참고 수준
- 설명문(전망·무관 문장)은 사람 판정에서 본 오류 유형을 보고 정했으므로, 학습 없는 방식이라도 완전히 독립적인 시험은 아님
- 50건이 모두 키워드에 걸린 기사라, 키워드가 아예 못 잡은 기사(놓친 진짜 기사)는 비교하지 못함
